# 데이터를 자동으로 해제하는 스마트 포인터

일반 포인터가 단순히 메모리 주소만을 담는 타입이라면, 스마트 포인터는 가리키는 데이터를 관리하기 위한 메타데이터나 자동 메모리 관리 기능을 갖춘 구조체입니다. 스마트 포인터는 트레이트와 제네릭을 적극 활용하여 구현되므로, 이를 잘 다루려면 두 개념에 대한 깊은 이해가 필요합니다.

스마트 포인터는 사실 평범한 구조체이지만, 다음 두 가지 핵심 트레이트를 구현하고 있어 특별한 능력을 발휘합니다.

1.  `Deref` 트레이트: 포인터가 가리키는 원본 데이터에 접근하는 역참조(`Dereference`) 기능을 제공합니다. 구조체인 스마트 포인터에 `*` 연산자를 사용할 수 있게 해주는 마법 같은 도구입니다.
2.  `Drop` 트레이트: 스마트 포인터가 자신이 속한 스코프(`Scope`)를 벗어날 때 자동으로 실행됩니다. 힙 메모리를 해제하거나 열려 있는 파일을 닫는 등의 자원 정리 작업을 수행합니다.

## 스마트하지 않은 로우 포인터 (Raw Pointer)

먼저 스마트한 기능이 전혀 없는 순수 포인터를 알아보겠습니다. 실무에서 직접 쓸 일은 드물지만, 외부 라이브러리를 분석하거나 임베디드 시스템을 개발할 때 꼭 필요한 개념입니다.

포인터는 선언할 때 반드시 가변(`mut`) 또는 상수(`const`) 여부를 명시해야 합니다.

```rust
fn main() {
    let mut mutablestr = String::from("mutable");
    let mutptr: *mut String = &mut mutablestr; // 가변 로우 포인터
    println!("Pointer={:?}", mutptr);

    let conststr = String::from("const");
    let constptr: *const String = &conststr; // 상수 로우 포인터
    println!("Pointer={:?}", constptr);
}
```

`C`/`C++`과 비슷해 보이지만 결정적인 차이가 있습니다. 바로 포인터 연산입니다. `Rust`는 포인터 주소에 정수를 더하는 식의 연산을 기본적으로 허용하지 않습니다. 실수하기 너무 쉽기 때문입니다.

굳이 하려면 컴파일러가 알려주는 대로 `wrapping_add` 같은 메서드를 사용해야 하며, 무엇보다 `unsafe` 블록 안에서만 실행할 수 있습니다.

```rust
unsafe {
    println!("Array={}", *ptr.wrapping_add(i));
}
```

`unsafe` 키워드는 "포인터가 `null`이거나 이미 해제되었을 수도 있지만, 내 책임하에 메모리에 직접 접근하겠다"는 선언입니다. `std::ptr` 매뉴얼에서는 직접 `*` 연산자를 쓰는 것보다 `read` 메서드 사용을 권장합니다.

## 데이터를 힙 영역에 저장하는 Box<T>

가장 대표적인 스마트 포인터입니다. 데이터의 타입에 상관없이 실제 값은 힙(`Heap`) 영역에 저장하고, 그 주소를 가리키는 포인터와 메타데이터는 스택(`Stack`)에 보관합니다.

*   스택(`Stack`): 데이터 크기가 컴파일 시점에 정해져야 하며, 실행 중 크기가 변할 수 없습니다.
*   힙(`Heap`): 데이터 크기를 미리 알 수 없거나 실행 중 유연하게 변해야 할 때 사용합니다.

`Box<T>`는 이 둘의 가교 역할을 하며 소유권을 관리합니다. `Box` 객체가 해제될 때 `Drop` 트레이트가 작동하여 힙에 저장된 실제 데이터도 함께 깔끔하게 지워줍니다.

### Box<T> 직접 구현해 보기

원리를 이해하기 위해 아주 단순한 스마트 포인터를 만들어 보겠습니다.

```rust
// code/smart_pointer_basic/main.rs
use std::ops::{Deref, DerefMut};

struct MySmartPointer<T>(T);

impl<T> Deref for MySmartPointer<T> {
    type Target = T;
    fn deref(&self) -> &T {
        &self.0
    }
}

impl<T> Drop for MySmartPointer<T> {
    fn drop(&mut self) {
        println!("자원을 해제합니다.");
    }
}

fn main() {
    let my_pointer = MySmartPointer::new(5);
    println!("Value: {}", *my_pointer); // Deref 작동
}
```

`deref` 메서드가 내부 데이터의 레퍼런스를 반환하므로 `*` 연산자로 값을 읽을 수 있습니다. 함수가 끝나면 `drop`이 자동으로 호출됩니다.

### 실전 활용: 트레이트 객체와 Box

`Box<T>`가 반드시 필요한 상황 중 하나는 트레이트 객체를 배열이나 벡터에 담을 때입니다.

예를 들어 사용자 ID(`UserID`)와 제품 ID(`ProductID`) 구조체가 모두 `GenSerialData` 트레이트를 구현했다고 합시다. 이들을 하나의 리스트에 모으고 싶을 때, 단순히 레퍼런스(`&dyn Trait`)를 쓰면 타입 불일치 에러가 발생합니다.

하지만 `Box`에 담으면 이야기가 달라집니다. 배열에 저장되는 것은 동일한 크기의 'Box 타입' 포인터가 되기 때문입니다.

```rust
// 서로 다른 타입을 하나의 리스트로 관리하기
let mut items: Vec<Box<dyn GenSerialData>> = vec![
    Box::new(userid),
    Box::new(productid)
];
```

이렇게 하면 루프를 돌며 각 객체의 메서드를 한꺼번에 호출할 수 있어 확장성이 매우 좋아집니다. 새로운 데이터 타입을 추가해도 트레이트만 구현하면 기존 코드를 수정할 필요가 없습니다.

## 다른 스마트 포인터들

상황에 따라 다양한 스마트 포인터를 사용합니다.

1.  `Rc<T>`, `Arc<T>`: 소유권을 여러 개로 나눠 데이터를 공유합니다. `Rc`는 싱글 스레드용, `Arc`는 멀티 스레드용입니다.
2.  `RefCell<T>`: 불변 참조를 가진 상태에서도 내부 데이터를 수정할 수 있게 해줍니다. (내부 가변성 패턴)
3.  `Mutex<T>`, `RwLock<T>`: 멀티 스레드 환경에서 데이터 접근을 제어하는 락(`Lock`) 기능을 제공합니다.

`Rust`의 강력한 메모리 안전성은 바로 이 스마트 포인터들이 소유권 규칙을 충실히 수행하기 때문에 가능한 것입니다.
